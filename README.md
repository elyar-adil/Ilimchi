# 页边 · Marginalia

一个轻量的学术论文 PDF 阅读器。PDF 直接在浏览器里从原站（arXiv 等）读取；高亮、批注、阅读进度和论文信息保存在**你自己的 GitHub 私有仓库**里，在任意设备登录同一个账号即可看到同一份笔记。

- 没有后端服务器，不依赖 Cloudflare Workers 或付费数据库。
- 论文 PDF 不上传到任何服务器，也不会写入 GitHub。
- 只存储笔记数据：每篇论文一个 JSON 文件（`papers/<id>.json`）。

## 设计

界面采用「页边」的设计语言：灵感来自编辑在校样页边用蓝铅笔批注。纸面是主角，界面退后；铅笔蓝是唯一的强调色，破坏性操作用红铅笔；论文标题与引文使用内嵌的 Source Serif 4 衬线体（中文回退到系统宋体），界面文字用系统无衬线；用发丝线和留白分组，不用卡片。

## 功能

- 粘贴 arXiv 链接或编号（点击右上角 + 打开添加面板）（`1706.03762`、`arxiv.org/abs/…`、`…v2`）、OpenReview、ACL Anthology，或任意 PDF 直链；也可以打开本地 PDF。
- 选中文字 → 五种颜色高亮，或添加批注。批注在侧栏编辑，点击可跳回 PDF 对应位置。
- 高亮位置以页面比例坐标和原文锚点（选中文字 + 前后文）共同保存，刷新、换设备后仍能精确恢复。
- 版本管理：arXiv 版本号（v1、v2…）、新版本提示、标签、搜索、阅读进度、回收站。
- 多设备并发修改自动合并：不同批注都会保留，删除也会同步。
- 备份：每次保存都是 GitHub 的一次提交（可回滚）；另外可导出/导入 JSON 备份。
- 文字框：在页面任意位置点击「文字」工具即可输入，字号随缩放等比变化；点击已有文字框可再次编辑。
- 画笔与橡皮：画笔支持四种颜色；橡皮点击笔迹即可删除。笔迹与文字框同样会同步到其他设备。
- 荧光笔：宽而半透明的笔迹，与纸面正片叠底，颜色可选黄、绿、蓝、粉。
- 触控与平板：笔负责书写；手指拖动翻页与平移，双指捏合缩放；笔在使用中（1.5 秒内）或大面积接触（手掌）时忽略触摸，防止误触。鼠标与键盘操作不受影响。触控板捏合与 Ctrl+滚轮只缩放阅读区。
- 删除需要确认：移入回收站、永久清除、删除批注或标注、删除标签、清除本机数据都会先弹出确认。橡皮擦除笔迹是即时操作。
- 论文整理：排序（最近阅读 / 添加时间 / 标题）；「未分类」视图；「整理」模式下可批量添加或移除标签、移入回收站、恢复或永久清除；侧栏可重命名或删除标签。
- 外观：模式（自动 / 浅色 / 深色）与夜间阅读方式（柔和 / 反色）分开设置。明暗是显示模式，不是主题；页面底色只在浅色模式下生效。
  - 柔和：整体降亮降对比，图片颜色基本保留。
  - 反色：文字更锐利，但图片也会一起反色。

## 工作原理

```
浏览器（纯静态页面）
 ├─ pdf.js 渲染 PDF（字节只在浏览器内存与本机 IndexedDB 缓存中）
 ├─ 本地优先：所有修改先写入 IndexedDB，离线也可用
 └─ GitHub Contents API ── 直连 api.github.com（允许浏览器跨域）
        papers/<id>.json   ← 笔记（每篇一个文件，每次保存是一次提交）
```

**并发与一致性**：推送使用 Contents API 的 `sha` 做乐观锁。若另一台设备先写入（返回 409），应用会拉取远端版本，用确定性的合并规则（标量字段按时间戳胜出、批注按 ID 取并集、删除使用墓碑）合并后重试。合并满足交换律、结合律与幂等性，有单元测试覆盖。

## 授权与安全

- **为什么用 fine-grained 个人访问令牌（PAT），而不是 OAuth 网页登录？** GitHub 的 OAuth 令牌交换接口不支持浏览器跨域调用，而且网页授权需要保密的 `client_secret`，只能放在后端。为了不依赖任何服务器，由你自己生成一个权限最小的令牌。
- 令牌只限一个仓库、只授予 `Contents: Read and write`。
- 令牌保存方式可选：
  - **仅本次会话**：关闭标签页即失效（最安全）。
  - **记住在本设备**：用不可导出的 AES-GCM 密钥加密后存入 IndexedDB；存储内容本身无法读出明文。
  - **口令解锁**：用 PBKDF2（60 万次迭代）从口令派生密钥，每次打开需输入口令（推荐用于共享电脑）。
- 令牌**不会**出现在源码、构建产物、Git 仓库或 localStorage 中；只发送到 `api.github.com`。
- 应用拒绝把笔记存入公开仓库（会提示改为私有）。
- 页面带有内容安全策略（CSP）：脚本只能来自同源，网络请求限制为 `https:`。
- 不会因为令牌是 PAT 而泄露到仓库：`.gitignore` 已排除常见的环境变量文件。

## 本地运行

需要 Node.js 20+（开发环境使用 22）。

```bash
npm install
npm run dev          # 开发服务器，http://localhost:5173
npm test             # 单元测试（71 项：ID 解析、锚点、合并、同步、GitHub 客户端、保险库）
npm run typecheck
npm run build        # 生成 dist/
npm run preview      # 本地预览生产构建
```

## 首次使用

1. 在 GitHub 新建一个**私有**仓库，建议名 `paper-notes-data`（可以是空仓库）。
2. 打开 <https://github.com/settings/personal-access-tokens/new>：
   - Repository access：只选上面的仓库；
   - Permissions → Contents：`Read and write`。
3. 打开应用，粘贴令牌，选择保存方式，点击连接。

## 单个 HTML 文件版本

`npm run build` 的产物 `dist/index.html` 已经是一个完整的单文件应用（约 2 MB，pdf.js 与其 worker、样式和脚本全部内联）。

- 直接用浏览器打开即可（`file://` 也能用），也可以上传到任何静态空间，包括 GitHub Pages。
- 因为是内联脚本，页面 CSP 允许 `'unsafe-inline'` 与 `blob:` 脚本；网络请求仍只允许 `https:`。
- 在 `file://` 下 IndexedDB 与 localStorage 的行为依浏览器而定；若发现本机数据未保存，建议改为通过 HTTP 访问同一文件。

## 部署到 GitHub Pages

仓库中的 `.github/workflows/pages.yml` 会在推送到 `main` 时自动测试、构建并发布。

1. 把代码推送到你的 GitHub 仓库（例如 `paper-reader`）。
2. 在仓库 **Settings → Pages** 中，Source 选择 **GitHub Actions**。
3. 推送后访问 `https://<你的用户名>.github.io/paper-reader/`。

应用本身不含任何数据或凭据，因此代码仓库可以公开；笔记只存在于你单独创建的私有仓库中。

## 已知限制

- **PDF 跨域**：浏览器直连论文站点需要对方允许跨域（CORS）。arXiv 的 PDF 页面是否允许，取决于其当时的策略；本次开发环境无法访问 arXiv，因此我**没有**在真实 arXiv 上验证直连，只在模拟环境中验证了流程。如果直连失败，应用会提示改用「打开本地 PDF」，或在设置中配置你自己的代理（可选，默认关闭）。笔记仍可照常同步，只是 PDF 需在每台设备上单独打开。
- 触控的惯性滚动暂未实现，手指拖动停止即停止。
- 本地文件论文按内容哈希识别，在另一台设备上需要重新选择同一个 PDF。
- 历史提交中的旧内容不会因为「彻底清除」而消失；如需彻底删除，需在 GitHub 上重写历史。
- 批注以 PDF 文本层为准。扫描版（无文本层）PDF 无法选中文字，因此不能高亮。
- 夜间模式是对整页做的近似处理，无法逐张识别图片。柔和模式下图片颜色基本保留；反色模式下图片会变色。
- 笔迹与文字框以页面比例坐标保存。页面尺寸（PDF 版本）改变时，它们会保持相对位置，但不会随内容重新定位。
- 所有页面在视口附近渲染，远离视口的页面保留渲染结果；超长 PDF 的内存占用会随已渲染页数增加。

## 项目结构

```
src/core/     纯逻辑：数据模型、合并、锚点、GitHub 客户端、同步引擎、保险库、PDF 缓存
src/pdf/      pdf.js 封装与文本层 ↔ 字符偏移映射
src/ui/       Preact 界面：登录、论文库（侧栏 + 列表）、阅读器（工具条、检查器）、设置面板、图标与样式
src/core/prefs.ts  仅保存在本设备的偏好：明暗模式、夜间方式、页面底色、PDF 代理（不含凭据）
tests/        Vitest 单元测试
```
